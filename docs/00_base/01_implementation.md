## 技術選定

### 採用する技術

| 領域 | 採用技術 | バージョン / 条件 | 採用理由 |
| --- | --- | --- | --- |
| 言語 | TypeScript / Rust | TS 5、Rust stable | 型安全な UI と Tauri ホスト |
| フレームワーク | Tauri / Svelte / Vite | Tauri 2、Svelte 5、Vite 7 | 小さい配布物、クロスプラットフォーム、短い開発サイクル |
| UI | Crepe (Milkdown) | 7.x | Markdown を保つ成熟した WYSIWYG 基盤 |
| 状態管理 | Svelte コンポーネント状態 | 外部ストアなし | MVP の状態量には十分で依存を増やさない |
| データ保存 | Tauri fs plugin | ユーザが選択した `.md` のみ | WebView に Node 権限を与えず OS API で安全に読み書き |
| 実行環境 | Tauri WebView | Windows 優先、macOS 対応可能 | OS 固有コードをアプリ層から排除 |

### 採用しない技術

| 技術 | 採用しない理由 | 再検討条件 |
| --- | --- | --- |
| Electron | MVP の軽量性という目的に対しランタイム同梱コストが大きい | Tauri/WebView 固有の重大な互換問題が判明した場合 |
| Milkdown Kit の個別構成 | Crepe で速く MVP と編集 UX を評価するため | 起動速度、メモリ、入力応答の計測で Crepe が目標を阻害した場合 |
| 自作エディタ | IME、選択、履歴、Markdown 変換を安定させるコストが高い | 再検討しない |

## 実装方針

### アーキテクチャ方針

- `src/lib/files.ts` がファイルダイアログと読み書きの境界を担当する。
- `src/lib/document.ts` は文書状態と純粋な更新処理を担当し、UI テスト可能にする。
- `Editor.svelte` が Crepe のライフサイクルを隔離し、アプリ状態へ Markdown 更新だけを通知する。
- `App.svelte` はサイドバー、選択、保存、通知を調停する。
- `src-tauri` は標準 plugin 登録と最小権限だけを持ち、Windows 固有ロジックを置かない。

### データ設計方針

開いている文書は `{ id, path, name, markdown, savedMarkdown }` とする。`markdown !== savedMarkdown` を未保存状態とし、保存成功時だけ `savedMarkdown` を更新する。永続形式は元の UTF-8 Markdown のみで、独自メタデータを混入しない。

### UI / UX 方針

- 左に固定幅の文書一覧、右側全面を編集面とする。プレビューペインは作らない。
- `Ctrl/Cmd+O` でファイル追加、`Ctrl/Cmd+S` で保存。ボタンにも tooltip と aria-label を付ける。
- Crepe のコードミラー、画像アップロード、数式を無効化し、文書編集に必要な基本ブロックへ絞る。
- 未保存は一覧の点とヘッダーで表示し、エラーは画面下のステータス領域へ表示する。

### エラーハンドリング方針

ダイアログのキャンセルは通常操作として無視する。読み書き失敗は文書状態を壊さず、利用者が再試行できるメッセージへ変換して表示する。保存成功前に dirty 状態を解除しない。

### テスト / 品質確認方針

| 種別 | 方法 / ツール | 対象 / 基準 | 補足 |
| --- | --- | --- | --- |
| Unit Test | Vitest | 文書生成、重複排除、更新、保存済み遷移 | OS API は純粋ロジックから分離 |
| Integration Test | Vitest + Testing Library | 空状態、文書一覧、切替、保存導線 | Crepe は境界でモック可能にする |
| E2E / 手動確認 | Vite ブラウザ表示 / Tauri dev | レイアウト、編集面、ショートカット | ネイティブダイアログは対象 OS で最終確認 |
| Lint / Type Check | svelte-check | エラー 0 |
| Rust Check | cargo check | Tauri ホストがコンパイル可能 |
| Build | vite build / tauri build (環境が許す範囲) | プロダクション生成成功 |

## 実装スコープ

### 今回実装すること

- Tauri 2 + Svelte 5 プロジェクトと Windows/macOS 共通設定
- Crepe 単一画面エディタ、基本 Markdown、不要 feature の停止
- 複数 `.md` のオープン、フォルダ配下 Markdown の再帰的な読み込み、一覧切替、編集状態保持、元ファイル保存
- 空状態、dirty 表示、操作通知、キーボードショートカット

フォルダ選択は Tauri dialog によりその実行中だけ追加される filesystem scope を利用し、読み込みは `files.ts` に集約する。フォルダを選んだ後はその配下を再帰列挙し、Markdown だけを開く。ファイル作成・削除・改名、外部変更監視は引き続き対象外とする。
- 文書状態の単体テストとビルド検証

### 今回実装しないこと

- フォルダ探索、ファイル作成/削除/改名、外部変更監視、セッション復元
- 自動保存、終了時確認、設定画面、テーマ切替、配布署名
- 高度な Crepe 機能（画像アップロード、数式、埋め込み、コード編集 UI）

## AIエージェント向け実装ルール

- Markdown 文字列を Source of Truth とし、独自形式へ変換して保存しない。
- ファイル権限は dialog で選択されたパスの読み書きに必要な最小範囲とする。
- ネイティブ API 呼び出しは `files.ts` に集約し、テスト時に差し替え可能にする。
- Windows 固有パス区切りを文字列で仮定せず、表示名抽出は両区切りに対応する。
- インポートを try/catch で囲まない。
