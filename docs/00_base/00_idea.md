# 軽量ローカル Markdown エディタ — アイデア

## アイデア概要

### 元のアイデア

Windows でまず動作し、将来 macOS にも展開できる、Notion のような単一画面のローカル Markdown エディタを作る。.md を直接開いて編集・保存し、複数ファイルを左サイドバーで切り替える。Markdown 記法は入力した場所で即座に見た目へ反映し、互換性を維持する。Tauri 2、Svelte、Crepe を第一候補とする。

### 一言でいうと

VS Code を起動するほどではない日常的な Markdown 編集を、軽く、速く、ファイルを手元に置いたまま行うデスクトップアプリ。

### 背景・目的

一般的な Markdown エディタの分割プレビューは視線移動が多く、汎用 IDE は簡単なメモ編集には重い。Markdown ファイルを唯一の保存形式としながら、記法を意識しすぎない直接編集体験を提供する。

### 想定ユーザ

- Windows でローカルの `.md` メモや文書を日常的に扱う個人
- 将来は同じデータと操作感を macOS でも使いたいユーザ

### 解決したい課題

- Markdown の入力と完成形の確認を別ペインで行う煩雑さ
- 複数のメモを行き来する際のファイルダイアログの反復
- 小さな編集のために汎用 IDE を起動するコスト

## 詳細化する観点

### 期待する利用シーン

アプリを起動し、ファイル追加ボタンから複数の `.md` を開く。左の一覧で文書を切り替え、中央の編集面に `#`、`>`、リスト等を入力するとブロックがその場で整形される。変更状態を確認し、保存ボタンまたは `Ctrl+S` で元ファイルへ保存する。

### 主要機能候補

- OS のファイルダイアログによる `.md` ファイルの複数選択
- 開いている文書のサイドバーと未保存表示
- Crepe による単一画面 WYSIWYG 編集
- Markdown の読み書きとキーボード保存
- エラーと操作結果の非侵襲的な通知

### MVP

- Windows デスクトップアプリとして起動できる
- ローカルの `.md` ファイルを直接、複数開ける
- 左サイドバーでファイルを切り替えられる
- 1つの編集面で Markdown を入力し、その場で見た目へ反映できる
- 編集結果を互換性のある Markdown として元ファイルへ保存できる
- 将来の macOS ビルドを妨げる OS 固有実装をアプリ層へ持ち込まない

### 非目標

- フォルダツリー、全文検索、Git、タブ、クラウド同期、共同編集
- Markdown 以外のファイル形式、画像管理、独自データベース
- Crepe の全機能や Notion の機能網羅
- 初回サイクルでの配布署名、インストーラ公開、厳密な性能保証

### 成功条件

- SC-01: Windows 向け Tauri 2 アプリの開発ビルドが成立し、画面が起動する。
- SC-02: ダイアログから複数の `.md` を読み込み、サイドバーで内容を切り替えられる。
- SC-03: 見出し、引用、リスト、強調、リンク、コード等の基本 Markdown を単一編集面で直接編集できる。
- SC-04: 変更状態が判別でき、`Ctrl+S` または保存操作で選択中ファイルへ Markdown を書き戻せる。
- SC-05: 型検査、フロントエンドテスト、プロダクションビルドが成功する。

すべての task 完了後に、MVP と上記の成功条件を満たしていることを確認する。

### 制約

- 第一対象は Windows、構成は Windows/macOS 共通の Tauri API に限定する。
- 編集基盤は自作せず Crepe を先に評価し、性能上の問題が測定された場合のみ Milkdown Kit を検討する。
- ローカルファイル以外へ文書内容を送信しない。
- 機能数より編集体験と起動の簡潔さを優先する。

## AIエージェントによる初期仮説

| 項番 | 仮説 | 理由 | 変わった場合の影響 | ユーザ確認 |
| --- | --- | --- | --- | --- |
| 1 | MVP は単一ウィンドウとする | 編集体験を優先し複雑性を抑える | ウィンドウ状態管理が必要 | 不要 |
| 2 | 外部変更の監視や競合解決は MVP 外 | 明示要望がなく、安全な自動解決は複雑 | ファイル監視と競合 UI が必要 | 要 |
| 3 | 未保存のままファイル切替は許可し、一覧に状態を保持する | 複数ファイル切替の快適さを優先 | 切替時確認または自動保存が必要 | 要 |
| 4 | ファイル一覧はアプリ終了時に永続化しない | ファイルアクセス権限と復元 UX を最小化 | 設定保存と復元処理が必要 | 要 |

## ユーザへの確認事項

MVP は上記仮説で自律実装する。外部変更検知、終了時の未保存確認、セッション復元は実利用の評価後に優先度を確認する。
