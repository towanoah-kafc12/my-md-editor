# Editor Lifecycle Tasks

アプリの終了、再起動、外部変更、自動保存など、文書の状態を安全に維持する機能をまとめる。

## 終了時の未保存確認

Status: 未着手

Priority: 高

Dependencies: なし

Success criteria: 該当なし

### Work

- [ ] 実装前にこのタスクの内容を確認し、未確定事項 / 実装範囲 / 受入条件を必要な粒度まで詰める
- [ ] アプリ終了要求を捕捉し、未保存のMarkdownがあるか確認する
- [ ] 未保存がない場合は追加操作なしで終了できるようにする
- [ ] 未保存がある場合は対象ファイルを利用者が把握できる形で表示する
- [ ] 保存して終了 / 破棄して終了 / 終了をキャンセル、の3操作を用意する
- [ ] 保存して終了では未保存ファイルをすべて保存し、すべて成功した場合だけ終了する
- [ ] 1件でも保存に失敗した場合はアプリを閉じず、失敗したファイルと理由を表示する
- [ ] 複数ファイルが未保存でも二重ダイアログや終了処理の多重実行が起きないようにする
- [ ] Windowsのウィンドウ閉じる操作で確認し、将来macOSでも同じ状態管理を再利用できる構造にする

### Done

- 未保存内容がある状態で、確認なしにアプリが終了しない
- 保存失敗時に未保存内容を保持したまま編集へ戻れる

## 外部ファイル変更の検知

Status: 未着手

Priority: 高

Dependencies: なし

Success criteria: 該当なし

### Work

- [ ] 実装前にこのタスクの内容を確認し、未確定事項 / 実装範囲 / 受入条件を必要な粒度まで詰める
- [ ] 開いているMarkdownファイルの外部変更を監視する方法を決める
- [ ] 変更イベントの連続発火をまとめ、同じ更新を複数回処理しないようにする
- [ ] Plainmark側が未編集なら外部変更後の内容を自動で再読込する
- [ ] Plainmark側にも未保存変更がある場合は自動上書きせず、Reload / Keep current を選べるようにする
- [ ] Reload選択時はディスク内容を読み直し、未保存状態を解消する
- [ ] Keep current選択時は現在の編集内容を維持し、次回保存時に外部内容を上書きすることが分かる状態にする
- [ ] Plainmark自身の保存を外部変更として誤検知しないようにする
- [ ] 外部でファイルが削除 / 移動された場合は編集内容を即時破棄せず、保存不能状態として利用者へ通知する
- [ ] 複雑な3-way mergeや自動競合解決は行わない

### Done

- VS CodeやAIエージェントなど別プロセスからファイルが変更されても、未保存内容を失わず安全に追従できる
- Plainmark自身の保存で不要な再読込や競合表示が発生しない

### Progress

### Note

外部変更とローカル未保存変更が同時に存在する場合は、安全性を優先して利用者へ選択させる。

## オートセーブ

Status: 未着手

Priority: 中

Dependencies: 終了時の未保存確認 / 外部ファイル変更の検知

Success criteria: 該当なし

### Work

- [ ] 実装前にこのタスクの内容を確認し、未確定事項 / 実装範囲 / 受入条件を必要な粒度まで詰める
- [ ] 設定でオートセーブをON / OFFできるようにする
- [ ] デフォルトはOFFとする
- [ ] 編集停止後のdebounce保存など、保存頻度が高くなりすぎない方式を決める
- [ ] アクティブ文書を切り替えた場合の保存有無を決める
- [ ] 外部変更を検知して競合状態にある文書は自動保存しない
- [ ] 保存成功後は通常の保存と同じ状態更新を行う
- [ ] 保存失敗時は未保存状態を維持し、利用者へ通知する
- [ ] 設定値を永続化する

### Done

- 利用者が明示的に有効化した場合だけ自動保存される
- 外部変更や保存失敗がある状態で自動的に内容を上書きしない
