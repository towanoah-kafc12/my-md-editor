# Task

現在進行中または後続へ持ち越す作業と、その現在の進捗を記録する。

単なるTODO一覧や作業履歴ではなく、複数セッションでも作業を再開できる状態を保つために使う。

## 記録するもの

- 複数の作業に分けて進める必要がある実装
- 別セッションへ持ち越す可能性がある作業
- 調査、検証、移行など、実施する内容が決まっている作業
- 実装中に新しく発生し、その場では完了しない作業

その場で完了できる軽微な作業は記録しない。

対応内容や方針自体がまだ決まっていない場合は `docs/02_open/` に記録する。後続でも必要になる判断は `docs/01_decision/` に記録する。

## ファイルの分け方

1つのタスクにつき1ファイルにはしない。

原則として、関連するタスクをテーマ単位で1ファイルにまとめる。

例:

- `auth.md`
- `database.md`
- `deployment.md`

同じテーマのタスクが増え、1ファイルでは扱いづらくなった場合はファイルを分ける。

同じテーマで複数ファイルに分かれ、直下では見通しが悪くなった場合だけ、そのテーマ名のディレクトリを作成してまとめる。

分割やディレクトリ化は必要になってから行い、将来を予測して先に構造を作らない。

## タスクの分け方

タスクは、完了したかどうかを明確に判断できる単位に分ける。

細かい手順まで事前に分解する必要はない。実装を進めながら必要になった場合は、タスクを追加または分割する。

複数のタスクに依存関係がある場合だけ、実施順序や依存先を記載する。

## 進捗の扱い

`Status`、`Work` のチェック状態、`Progress` を現在の作業状態のSource of Truthとする。`Status` は未着手、進行中、ブロックを使う。

作業を中断または終了する前に、次のセッションがそのまま再開できるように現在の状態と次に進める箇所を更新する。

`Progress` には作業履歴を追記し続けず、現在の状態だけが分かるように上書きする。

## 自律タスク運用

### 次タスクの選択

複数のtaskがある場合は、次の順で選ぶ。

1. 進行中のtaskを継続する。
2. 依存関係が解消済みのtaskを選ぶ。
3. `Priority` が高いtaskを優先する。
4. `docs/00_base/00_idea.md` の成功条件への寄与が大きいtaskを優先する。
5. それでも同じ場合は記載順に進める。

### 実行ループ

選んだtaskを、選択 → 実装 → 検証 → 受入確認（`Done`）→ 完了 → 次taskの順に進める。検証が失敗した場合は原因を修正して再検証する。

可逆的なリポジトリ内編集、既存の検証、taskの更新は自律的に進めてよい。不可逆な操作、外部環境の変更、secretの変更、ユーザ判断が必要な仕様、未解消の依存関係、検証不能または安全に解消できない失敗では停止する。方針が未確定なら `docs/02_open/`、長期的な判断なら `docs/01_decision/` に記録する。

## 完了条件

各タスクの `Done` を受入確認として、何をもって完了とするかを記載する。成功条件に寄与するtaskは `docs/00_base/00_idea.md` の `SC-xx` を参照する。

テストや品質確認は `docs/00_base/01_implementation.md` の方針に従い、実行結果を `Verification` に記載する。実行していないテストや確認を成功扱いしない。必要な確認が完了していないタスクは完了扱いにしない。

## 完了したとき

完了したタスクは削除する。

ファイル内のすべてのタスクが完了した場合は、そのファイル自体を削除する。

完了したタスクを保存するためのアーカイブは作らない。過去はGit履歴を参照する。

すべてのタスクが完了したら、`docs/00_base/00_idea.md` のMVPと成功条件を満たしていることを確認する。満たしていない場合は、必要に応じて新しいtaskまたはopenを作成する。

## 記録形式

新しいtaskは以下の形式を使う。既存taskを新しい項目へ一括移行する必要はなく、更新時にも必要な情報だけを追加する。

## <タスク名>

Status: 未着手 / 進行中 / ブロック

Priority: 高 / 中 / 低

Dependencies: なし / <先行taskまたは外部条件>

Success criteria: SC-xx / 該当なし

### Work

- [ ] 実装前にこのタスクの内容を確認し、未確定事項 / 実装範囲 / 受入条件を必要な粒度まで詰める
- [ ] 実施する作業
- [ ] 実施する作業

### Done

- 完了と判断する条件

### Verification

<!-- 実行したテスト・確認と結果を記載する。未実施ならその理由を記載し、完了扱いにしない。 -->

### Progress

<!-- 進行中またはブロック中の場合に、現在の状態と次に進める箇所を簡潔に記載する。履歴は残さず最新状態へ更新する。 -->

### Note

<!-- 必要な場合だけ、タスク固有の確認方法、注意事項などを記載する。 -->
