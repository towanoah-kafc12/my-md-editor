# Open

次に実行する作業または採用方針が現在決められない事項を記録する。

解決済みの事項や、その場で対応できる内容、実行可能な調査・検証・修正・改善は残さない。

## 記録するもの

- ユーザの確認を待っていること
- 採用する方針を保留していること
- 修正方針が未確定な不具合
- 対応内容が未確定な改善事項

実行可能な調査・検証・修正・改善は `docs/03_task/` に記録する。対応内容または方針が未確定な場合だけ `docs/02_open/` に記録する。

## ファイルの分け方

1つの未解決事項につき1ファイルにはしない。

原則として、関連する未解決事項をテーマ単位で1ファイルにまとめる。

例:

- `auth.md`
- `database.md`
- `deployment.md`

別々に確認や対応することが増えたテーマはファイルを分ける。

同じテーマで複数ファイルに分かれ、直下では見通しが悪くなった場合だけ、そのテーマ名のディレクトリを作成してまとめる。

分割やディレクトリ化は必要になってから行い、将来を予測して先に構造を作らない。

## 解決したとき

解決した事項はファイルから削除する。

ファイル内のすべての事項が解決した場合は、そのファイル自体を削除する。

解決結果のうち、後続でも必要になる重要な判断だけを `docs/01_decision/` に記録する。

解決済み事項を保存するためのアーカイブは作らない。過去はGit履歴を参照する。

## 記録形式

同じファイル内に、以下の形式で未解決事項を追加する。

## <未解決事項>

### Context

何が未解決なのか。必要なら現在分かっていることや影響も記載する。

### Next

何を確認 / 判断 / 対応すれば解決できるか。
